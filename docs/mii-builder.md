# Native Mii editor

## Miis screen

Mac: Player → Miis… (Shift-Command-M), or Settings → Game & Data → Miis…, opens the Miis window. iPhone/iPad: Player Identity opens the same screen full screen (`apple/shared/KartPadMiiBrowser.inc.mm`). It uses the editor's Mii Channel look: a pinstriped background, a grid of portrait tiles (each Mii's head rendered from the imported RFL archive, with a favorite-color dot) and a details card for the selected Mii. Without the archive, tiles show a favorite-color silhouette and the details say why. Portrait wells stay light in dark mode, like the editor's artwork tiles.

- **Grid:** click or tap a tile to select it. Double-click a tile (Mac) or press Return to open it in the editor. The last tile is **New Mii**. Arrow keys move the selection, Delete removes and Escape closes, on Mac and on iPad hardware keyboards. A right-click (Mac) or long press (iPhone/iPad) on a tile offers Edit, Rename, Duplicate, Export and Remove; VoiceOver lists the same actions.
- **Details:** portrait, name, slot and creator, favorite color, how many licenses race as the Mii, then **Edit Mii**, **Rename…** (also renames every linked license, keeping friend codes and progress), **Duplicate** (opens the editor on Profile with a copy that has a fresh Mii ID and this console's ID, saved as a new Mii), **Export…** (a standard 74-byte `.mii`) and **Remove…**. A Mii can't be removed while it is the last one or while a license races as it.
- **Licenses:** each license that races as the selected Mii is listed with its profile and slot. Its ⋯ menu renames or deletes it. **Use for a License…** moves another license to this Mii, keeping its progress and friend code. Licenses whose Mii is missing appear under the grid with **Choose Mii…** to repair them.
- **Import:** **Import .mii…** in the footer, or drag `.mii` files onto the screen (Mac, iPad). Tiles drag out to Finder or Files as `.mii` files.
- **Pending changes:** every change is staged for the next launch, and only one can wait at a time. While one is waiting, a banner says what will change and how to apply it (Mac adds a Quit KartPad button). Every action except Export is disabled until KartPad restarts.
- **Sound:** the screen plays the editor's menu sounds and shares its Sound switch.

The Player menu keeps Create Mii…, Edit Mii → *name* and Import Mii…, which act through the Miis window. The editor opens above the Miis window, which sits above the game window.

## Editor

The editor uses the Wii category order: Profile, Body, Face, Hair, Eyebrows, Eyes, Nose, Mouth, Facial Hair, Glasses. All 46 appearance fields remain available. Visual tiles map explicitly to binary IDs; opening a category reveals the selected feature's page. Face shape/details and mustache/beard are two-part switches that name both pages and highlight the one showing; the mole is an on/off switch. Tiles run in Mii Channel order and show each feature in the Mii's current colours (skin, hair, eye, eyebrow, lip, glasses and facial-hair colours). Face shape tiles are outlines of the whole head drawn at one shared scale, so jaw shapes can be compared. The faceline mesh is open at the top (RFL leaves the crown to the hair meshes), so the bald style's forehead and scalp close it in skin colour. Artwork tiles stay light in dark mode. On Mac the pointer lights a button's rim in Wii blue and shows a pointing hand; iPad trackpads and mice get the same highlight.

Shared vector artwork follows the Mii Channel look: silver rounded-rectangle buttons on a solid ledge with a double rim, on a pinstriped background, Wii-blue selection, one icon set for the categories, preview turning, undo/redo and adjustments (move, size, rotate, spacing), color chips with a check on the selected one, drawn on/off switches for Favorite, Mingle, Flip hair and Mole, and height/weight gauges with a recessed track, notches, a ledged handle and small/large Mii silhouettes at the ends. The gauges support dragging, arrow keys (Shift for larger steps) and VoiceOver adjust; one drag is one history entry. The editor follows the system light/dark setting on Mac and the launcher's theme on iPhone/iPad; the preview background matches. AppKit and UIKit retain native text fields and scroll views. Male and Female are separate choices. Mac birthdays use named month and day menus; iPhone/iPad use a month/day wheel without a year. February allows 29 days because the Mii record has no birth year. Selecting Not set clears both fields. Name entry preserves the ten UTF-16-unit storage limit and waits for composed input to finish before validation. Emoji may consume multiple units.

Create Mii starts with Male/Female and Start from scratch, then opens Face. Existing Miis open directly. Cancel and Save & Quit sit below the editing panel. Save & Quit is the highlighted action and activates when the draft changes. Cancel closes an unchanged draft straight away and asks before discarding changes. Reset Changes and closing an edited draft also require confirmation. Export and Reset are in the secondary menu. Saving explains that KartPad must fully restart. New Miis remain unassigned until a license uses them: Use for a License… on the Miis screen, or License Settings → Change Mii in the game.

Buttons have accessible labels, selected states and visible keyboard focus. Mac supports arrow navigation, Return/Space, Cmd-Z, Cmd-Shift-Z and Escape; iPad hardware keyboards support undo, redo and Escape. Continuous button adjustments and slider drags produce one history entry. Adjustment buttons disable at the field limits and name their direction (for example Move up, Larger, Closer together) for VoiceOver and tooltips. Eye and eyebrow rotation is labelled as tilt: raising the value turns each feature about its inner end so the outer ends rise (Tilt outer ends up), matching the renderer. UIKit selection activates on release so scrolling does not select a choice on touch-down. The preview animates by default; **⋯ → Animate Preview** turns it off (saved per device):

- **Blink and smile** use RFL's own expressions (RFL_MakeTex.c): blinking swaps in eye texture 26 and smiling eye texture 48, with the eye rotation corrected by the difference in per-texture rotation offsets. Blinks come every 2.4–6 s, sometimes doubled; picking a feature or colour shows the smile for a second.
- **Body idle** plays the medium build's 50-frame `wait` loop from `MiiBody.szs` at one frame per 60 Hz tick (NW4R's default rate; the rate the game uses on its menus is not confirmed). Small and large models only have a one-frame `wait` (small's is a raised-arm wave), so they reuse the medium loop's motion as per-frame changes on large's `wait` pose and small's `stand` pose. The head follows the neck joint's position and the loop's own turning, not the neck's base orientation. Re-posing runs on the CPU into triple-buffered vertex buffers.
- **Head sway** is a slow drift of a few degrees. It is not from the game files. It fades out while the Mii is being turned by hand and returns after a moment. Opening a face category eases the Mii back to the front.
- Reduce Motion keeps blink and smile and drops the body loop, sway and easing. The preview only renders continuously while animating, on screen and in an active app; otherwise it draws on demand as before.

**Sound.** The editor plays Mario Kart Wii's own menu sounds (`SE_UI_*`). A Wii-style **Sound** checkbox sits in the top-right corner (next to undo/redo, or alone on the Create screen); it is on by default and saved per device. The mapping lives in `runtime/include/kartpad/mii/editor_sounds.h`:

- Opening the editor or birthday sheet: `CTRL_WIN_POPUP`. Leaving without changes, Keep Editing, Cancel: `CTRL_WIN_POPDOWN`. A confirmation appearing: `YESNO_POPUP`.
- Category tabs, page modes, colour swatches, face front, Mac birthday menus: `TAB_OK`. Part tiles and the ⋯ menu: `BTN_OK`. Gender, toggling on, Done, Animate Preview: `RADIO_OK`. Choosing what is already chosen, toggling off, nothing to undo or redo: `TAB_OK_NONE`. Start from scratch: `MATCH_CAPSULE_MII`.
- Adjustments and turning: `UD_LEFT` / `UD_RIGHT` on the first press; held repeats tick with `BTN_IN`, and a hold that reaches the limit plays `CTRL_REJECT`. Height and weight tick every 8 of 128 steps while dragging and on every key or VoiceOver step.
- Pages, undo and redo: `PAGE_PREV` / `PAGE_NEXT`; discarding or resetting changes also plays `PAGE_PREV`. Typing a name: `TENKEY_OK`; deleting: `TENKEY_ERASE`.
- Save or export: `DATA_SEND_OK`. Invalid names, save/export errors, pending-restart and unreadable Miis: `CTRL_REJECT`. Pointer hover (Mac, iPad trackpad): `BTN_IN`, which never cuts off another sound; every other sound replaces the one playing.

Sounds are rendered once per session on a background queue from the imported `files/sound/revo_kart.brsar` by `runtime/include/kartpad/audio/sound_archive.h`, an independent bounds-checked NW4R reader. It plays each sound's sequence through its instrument bank and DSP-ADPCM/PCM samples. Volume, pan, transpose, pitch bend, portamento, envelopes and note timing follow the sequence; sweeps apply instantly and LFO, filters and effect sends are not modelled, so the sounds are close to the game's, not identical. Nothing is cached on disk or shipped. Without the archive, or for a sound that fails to render, the editor stays silent. Playback uses the app's existing audio session, so the iPhone/iPad silent switch applies. The opening sound is requested before rendering finishes and plays if the sounds are ready within 1.5 s (about 0.9 s on a freshly booted iPhone simulator); otherwise it is skipped.

Mac defaults to 960 × 720 with an 800 × 600 minimum. Wide layouts show preview and editing panel side by side. The preview card carries the Mii's name and the turn left, face front and turn right controls. Pages show a pager only when a feature has more than one page; feature artwork is cropped and centred in its tile. Profile uses two columns when the panel is wide enough. Portrait iPhone places the preview above controls and splits category tabs across two rows. Editing panels scroll when needed. Regular adjustments update the affected controls and preview without rebuilding the form.

## Persistence

Save stages changes for the next cold launch. Export and discarded drafts leave live data untouched. Standard `.mii` records remain exactly 74 bytes. Hidden console identifiers, creation flags and reserved bits remain intact on edits. New identities use the runtime console MAC and a unique regular-Mii creation ID. Renaming an existing Mii updates matching licenses in Original and both Retro Rewind save locations.

`PendingMiiEditor.plist` holds one validated combined edit. On restart every target is checked before backups are written to `MiiEditorBackups`. Linked-name patches are rebased onto newer race progress if the license identity and previous name still match. A stale Mii or changed linked identity rejects the edit.

`MiiEditorTransaction.plist` is written before any live file changes. Atomic replacements apply the combined edit. An interrupted transaction rolls forward on the next launch; gameplay is blocked until recovery succeeds. Backups retain the pre-application database and saves. Pending changes prevent another import, removal, creation or edit. There is no save-format migration.

## Imported resources and rendering

`files/contents/RFLRes01.arc` supplies original head meshes and feature textures. `files/Scene/Model/MiiBody.szs` supplies original small, medium and large male/female body meshes, standing animation, diffuse textures, light maps, highlight maps, material assignments and attachment data. These are the game package's racing outfits. No invented body geometry or replacement facial-feature artwork is used. Mii Channel clothing and interface assets are not present in this imported package; toolbar artwork is reconstructed as vectors from the Wii manual.

A shared Metal renderer in `MTKView` supports drag rotation, rotation buttons, front reset, viewport fitting and full-body/head framing. Resource readers validate bounds, primitives, matrix indices, finite geometry, texture dimensions and cache data. Positions, normals and UV coordinates use their separate original scales. Mirrored meshes preserve normals and winding. Face-mask composition uses original feature textures and recoloring. Transparent overlays do not write depth; filtering handles alpha without black fringes. Body vertex alpha is a light-map coefficient, while diffuse alpha masks highlights. Material IDs come from the original draw bytecode. Original attachment offsets align the collar and head.

Glasses textures use the original GX addressing modes, including mirrored U coordinates spanning both lenses. The GPU sampler and CPU thumbnail renderer preserve clamp/repeat/mirror metadata. Accessory thumbnails show both sides of the imported mesh; shared triangle edges are not blended twice.

Resources load on a serial background queue. Decoded resources and thumbnails are cached; stale revisions are discarded before installation. Archive SHA-256 and cache version invalidate replaced or incompatible data. Missing head/body resources or Metal availability produce a readable state, while editing and export remain available. Imported resources and decoded caches are not shipped in app packages.

## Validation and limits

Run `scripts/test-mii-builder.sh /absolute/path/to/RFLRes01.arc /absolute/path/to/MiiBody.szs /absolute/path/to/revo_kart.brsar`. Without resources, binary, history, sound-archive and Apple persistence tests still run. Sound-archive tests build synthetic archives (PCM8, PCM16 and DSP ADPCM waves, transposition, note timing, release tails, conditionals, endless loops, non-advancing sequences, truncation and a corruption sweep); with the real archive every editor sound must render audibly. Tests use disposable databases and synthetic saves. Coverage includes all 46 field boundaries, Unicode, reserved/identity preservation, capacity, unique IDs, linked-name/progress preservation, stale records, backups, interrupted recovery, creation, explicit feature mappings, selected pagination, grouped undo/redo, stale preview revisions, month lengths, decoded resources, addressing modes and malformed archives/caches.

Local verification artifacts are recorded in `outputs/Wii-Mii-Editor-Review` outside the repository. The Metal catalog renders 870 front/side/back checks across every feature ID and palette, body extremes and hair reversal. Native screenshots and package audit results are recorded separately in that review folder.

Exact visual parity remains unverified. Feature IDs are mapped explicitly in Mii Channel order (hair, eyebrows, eyes, nose and mouth are non-sequential; the rest are sequential), taken from MiiJS's Mii Channel page tables and not yet checked against a console screen by screen. Body size follows the game: height + weight above 150 is a large Mii, above 104 medium, otherwise small (RMCP01 `0x80525FF4`). There is no continuous stretching; the preview swaps between the `sa_`, `ma_` and `la_mii` models and places the head with that build and gender's `miiDispParam.bin` head scale and Y/Z offset (menu copy in `MiiBody.szs`). The Body page names the current build. The lighting environment remains an approximation. Larger text scales within fixed controls; a full accessibility-size reflow is not implemented. Physical-device verification, every adjustment combination and an in-game rendering comparison are outstanding. These limits must not be presented as completed release gates.
