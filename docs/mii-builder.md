# Native Mii editor

## Miis screen

Mac: HOME → Miis, or Game → Miis… (Shift-Command-M), opens the Miis screen. iPhone/iPad: Player Identity opens the same screen full screen (`apple/shared/KartPadMiiBrowser.inc.mm`). It uses the editor's Mii Channel look: a pinstriped background, a grid of portrait tiles (each Mii's head rendered from the imported RFL archive, with a favorite-color dot) and a details card for the selected Mii. Without the archive, tiles show a favorite-color silhouette and the details say why. Portrait wells follow the light or dark theme.

- **Grid:** click or tap a tile to select it. Double-click a tile (Mac) or press Return to open it in the editor. The last tile is **New Mii**. Arrow keys move the selection, Delete removes and Escape closes, on Mac and on iPad hardware keyboards. A right-click (Mac) or long press (iPhone/iPad) on a tile offers Edit, Rename, Duplicate, Export and Remove; VoiceOver lists the same actions.
- **Details:** portrait, name, slot and creator, favorite color, how many licenses race as the Mii, then **Edit Mii** (followed by **Use for a License…** when no license races as the Mii yet, such as a new one), **Rename…** (also renames every linked license, keeping friend codes and progress), **Duplicate** (opens the editor on Profile with a copy that has a fresh Mii ID and this console's ID, saved as a new Mii), **Export…** (a standard 74-byte `.mii`) and **Remove**. A Mii can't be removed while it is the last one or while a license races as it.
- **Names:** Rename… for a Mii or a license uses the editor's rules: a live "*n* of 10 characters" count under the field, or what is wrong with the name in red, and the Rename button only while the trimmed name can be stored.
- **Selection after a change:** the Mii a change concerns is selected and scrolled to: an edited Mii, a new Mii, a duplicate or the first imported Mii. Removing a Mii selects the next one (the previous one for the last).
- **Licenses:** each license that races as the selected Mii is listed with its profile and slot. Its ⋯ menu renames it (**Rename License…**) or deletes it (**Delete License**). **Use for a License…** moves another license to this Mii, keeping its progress and friend code. Licenses whose Mii is missing appear under the grid with **Choose Mii…** to repair them.
- **Import:** **Import…** at the top right, or drag `.mii` files onto the screen (Mac, iPad). Tiles drag out to Finder or Files as `.mii` files.
- **Pending changes:** every change is queued for the next launch, and any number can wait. Each one builds on those before it, so the Miis screen shows Miis and licenses as they will be. A banner names the latest change (including a save in the editor, such as “Bob” will be added or “Bob” will be updated), counts what is waiting and says how to apply it (Mac adds a Restart button, and the Game menu has Restart to Apply). Discard drops every waiting Mii and license change after a confirmation; it also appears when a waiting change no longer fits the files and the Miis can't be shown. If waiting changes can't be applied at launch, the alert offers Discard Mii Changes, which starts the game with Miis and licenses as they are. A license queued for deletion stays listed, marked, with its actions disabled. A pending ghost import or save restore still waits alone and disables Mii actions until KartPad restarts.
- **Sound:** the screen and the editor play the Mii Channel menu sounds. On Mac, Settings → Sound controls them: HOME and Mii sounds turns them off, and the Sound switch and Master volume apply to them as to the game. iPhone/iPad have a Sound switch on the screen and in the editor.

The Game menu has Miis… (and Restart to Apply when changes are waiting); creating, editing and importing happen on the Miis screen. Closing the Miis screen returns keyboard focus to the game window. The editor opens above the Miis window, which sits above the game window. Mac has one editor at a time: asking for the Mii it already shows brings it forward, and asking for another Mii closes it first with the usual Save / Keep Editing / Discard Changes question (Keep Editing leaves it open).

Wording is shared between the screens: Mac says Restart KartPad and iPhone/iPad say to fully close KartPad from the app switcher and reopen it; alert titles use title case and errors read "*Thing* Couldn’t Be *Done*".

## Editor

The editor uses the Wii category order: Profile, Body, Face, Hair, Eyebrows, Eyes, Nose, Mouth, Facial Hair, Glasses. All 46 appearance fields remain available. Visual tiles map explicitly to binary IDs; opening a category reveals the selected feature's page. Face shape/details and mustache/beard are two-part switches that name both pages and highlight the one showing; the mole is an on/off switch. Tiles run in Mii Channel order and show each feature in the Mii's current colours (skin, hair, eye, eyebrow, lip, glasses and facial-hair colours). Face shape tiles are outlines of the whole head drawn at one shared scale, so jaw shapes can be compared. The faceline mesh is open at the top (RFL leaves the crown to the hair meshes), so the bald style's forehead and scalp close it in skin colour. Artwork tiles stay light in dark mode. On Mac the pointer lights a button's rim in Wii blue and shows a pointing hand; iPad trackpads and mice get the same highlight.

Shared vector artwork follows the Mii Channel look: silver rounded-rectangle buttons on a solid ledge with a double rim, on a pinstriped background, Wii-blue selection, one icon set for the categories, preview turning, undo/redo and adjustments (move, size, rotate, spacing), color chips with a check on the selected one, drawn on/off switches for Favorite, Mingle, Flip hair and Mole, and height/weight gauges with a recessed track, notches, a ledged handle and small/large Mii silhouettes at the ends. The gauges support dragging, arrow keys (Shift for larger steps) and VoiceOver adjust; one drag is one history entry. The editor follows the system light/dark setting on Mac and the launcher's theme on iPhone/iPad; the preview background matches. AppKit and UIKit retain native text fields. The Male and Female figures are Mii-proportioned vector silhouettes (large head, mitten arms; female in an A-line dress), reconstructed rather than taken from the Wii. Mac birthdays use named month and day menus; iPhone/iPad use a month/day wheel without a year. February allows 29 days because the Mii record has no birth year. Selecting Not set clears both fields. Name entry preserves the ten UTF-16-unit storage limit and waits for composed input to finish before validation. Names are checked and saved without surrounding spaces, as license names are. Under each name field a live count ("5 of 10 characters") turns into the problem in red when there is one. Emoji and some symbols take up more than one character, which the field's tooltip (Mac) or VoiceOver hint says.

Create Mii opens on a start screen: a small Male/Female switch above two choices, **Start from scratch** (the blank face, shown as its portrait) and **Choose a look-alike**. Look-alikes are a grid of 12 random faces (`LookAlike` in `runtime/include/kartpad/mii/editor.h`), with Shuffle for new ones and Back; changing gender redraws the same shuffle. RFL's own random tables are not documented, so faces draw from the Mii Channel part lists (everyday eyes, eyebrows and mouths from their first pages; hair pages 1–3 for male and 4–6 for female, with some crossover) and keep default positions and sizes. Faces render as portraits from the imported RFL archive; without it the tiles show plain face icons and the screen says why. Either choice opens Face. **⋯ → Start Over…** returns a new Mii to this screen with the same shuffle, asking first if the face was edited. Existing Miis open directly. Cancel and Save sit below the editing panel. Save is the highlighted action and activates when the draft changes. Cancel closes an unchanged draft straight away and asks before discarding changes. Reset Changes and closing an edited draft also require confirmation; closing asks Save Changes to “*name*”?. Export (named after the Mii) and Reset are in the secondary menu. Saving closes the editor without an alert: the Miis screen's banner names the change and explains the restart, and the saved Mii is selected. New Miis remain unassigned until a license uses them: Use for a License…, which the Miis screen shows right under Edit Mii for them, or License Settings → Change Mii in the game. On Mac the window title names the Mii (Edit Mii — *name*) and the close button's dot marks unsaved changes.

Buttons have accessible labels, selected states and visible keyboard focus. Mac supports arrow navigation, Return/Space, Cmd-Z, Cmd-Shift-Z and Escape; iPad hardware keyboards support undo, redo and Escape. Continuous button adjustments and slider drags produce one history entry. Each adjustment is a pair of buttons around its title: on one row when the column is wide enough for the longest title, otherwise with the title above the buttons. VoiceOver reads where the adjustment sits in its range on the buttons (for example "13 of 19"). Adjustment buttons disable at the field limits and name their direction (for example Move up, Larger, Closer together) for VoiceOver and tooltips. Eye and eyebrow rotation is labelled as tilt: raising the value turns each feature about its inner end so the outer ends rise (Tilt outer ends up), matching the renderer. UIKit selection activates on release so scrolling does not select a choice on touch-down. The preview animates by default; **⋯ → Animate Preview** turns it off (saved per device):

- **Blink and smile** use RFL's own expressions (RFL_MakeTex.c): blinking swaps in eye texture 26 and smiling eye texture 48, with the eye rotation corrected by the difference in per-texture rotation offsets. Blinks come every 2.4–6 s, sometimes doubled; picking a feature or colour shows the smile for a second.
- **Body idle** plays the medium build's 50-frame `wait` loop from `MiiBody.szs` at one frame per 60 Hz tick (NW4R's default rate; the rate the game uses on its menus is not confirmed). Small and large models only have a one-frame `wait` (small's is a raised-arm wave), so they reuse the medium loop's motion as per-frame changes on large's `wait` pose and small's `stand` pose. The head follows the neck joint's position and the loop's own turning, not the neck's base orientation. Re-posing runs on the CPU into triple-buffered vertex buffers.
- **Head sway** is a slow drift of a few degrees. It is not from the game files. It fades out while the Mii is being turned by hand and returns after a moment. Opening a face category eases the Mii back to the front.
- Reduce Motion keeps blink and smile and drops the body loop, sway and easing. The preview only renders continuously while animating, on screen and in an active app; otherwise it draws on demand as before.

**Controllers (Mac).** While the Miis window or the editor is open, connected controllers drive them and the game ignores the pads (and the keyboard); once both close it has them back at once, except what is still held then (the B that closed a window), which it doesn't hear until that is let go. The D-pad or left stick moves the focus ring to the nearest control in that direction (moving onto a Mii selects it) and repeats while held. It prefers a control straight ahead, then one more ahead than to the side; it stays within a scrolling list first, so Miis scrolled out of sight are reached row by row, and otherwise skips controls scrolled away. Down from a category tab goes into its page (the current choice). The editor's arrow keys move the same way; A presses the focused control, and held adjustments repeat as with the mouse. B is Done on the Miis screen; in the editor it closes (asking about unsaved changes), or steps back from the look-alike grid. In the editor LB/RB change category, X/Y undo and redo, Start saves, left/right step the height and weight gauges and the right stick turns the Mii (half a turn a second at full tilt); Start is Done on the Miis screen. In alerts the D-pad moves the default button, A presses it and B picks Cancel or Keep Editing; pop-up menus take the D-pad and A, and B closes them. A and B are the bottom and right face buttons, as in the game. A press while the game window is in front brings the Mii window back. Any press hides the mouse pointer until the mouse moves. File panels (Import, Export) take the D-pad as arrow keys, A as Return, B as Escape and LB/RB as Shift-Tab/Tab, which move between the sidebar, the files and the buttons. `apple/shared/KartPadMiiGamepad.inc.mm` maps the presses; the shell reads the pads on a timer that keeps running inside alerts and menus (`apple/macos/KartPadMacMiis.inc.mm`).

**Opening from a controller (Mac).** HOME → Miis opens the Miis screen with the focus ring already on the selected Mii. HOME opens with the controller's HOME button, or by holding Menu for a second.

**Controller keyboard (Mac).** Names are typed on a Wii-style keyboard (`apple/shared/KartPadMiiPadKeyboard.inc.mm`) above the window: a name well with the live count (or what is wrong, in red), letters and digits, a second page of accented letters and punctuation, and Shift, Space, Delete, Cancel and OK. The D-pad moves between keys (wrapping at the edges), A types, B deletes, X is Shift (once for one capital, twice for caps lock; it comes on by itself for an empty name), Y types a space, LB/RB switch pages and Start is OK. It never takes more than ten characters, and OK refuses an empty name where one is required. In the editor the Nickname and Creator fields are stops for the D-pad and A opens the keyboard; the keys go through the field's own editor, so a typed name is one undo step, and Cancel puts the field back. An alert asking for a name (Rename…, Rename License…) opens the keyboard by itself when the pad brought it up, or on any press other than B (which cancels); its OK presses Rename and its Cancel cancels the alert. The mouse and a hardware keyboard also work on the keyboard.

**Controller-only flow (Mac).** Every Mii and license task can be done with a controller alone:

| Step | Controller |
| --- | --- |
| Open the Miis window | HOME, then Miis |
| Choose a Mii | D-pad/stick; moving onto a Mii selects it |
| Create, edit | A on New Mii or a Mii tile, or on Edit Mii |
| Rename a Mii or license | A on Rename… (license: A on its row, then Rename License…), type on the keyboard, Start |
| Duplicate, remove, discard waiting changes | A on the button; confirmations take the D-pad, A and B |
| Use for a License…, Change Mii…, Delete License | A opens the menu; D-pad and A choose, B closes |
| Import, export | A on Import… or Export…; file panels take the D-pad, A, B and LB/RB |
| Edit features | D-pad, A, LB/RB category, X/Y undo/redo, left/right on height and weight |
| Nickname, Creator | D-pad to the field, A, type, Start |
| Birthday | A on month or day; the menu takes the D-pad and A |
| Save, close | Start saves; B closes (asking about unsaved changes) |
| Apply changes | A on Restart KartPad in the banner |
| Back to the game | B or Start on the Miis screen |

Not covered: the launch alert offered when waiting changes can't be applied (it appears before controllers are read) and the Export panel's file name (the default is the Mii's name).

**Sound.** The editor plays Mario Kart Wii's own menu sounds (`SE_UI_*`). On Mac they follow Settings → Sound (HOME and Mii sounds, the Sound switch and Master volume). On iPhone/iPad a Wii-style **Sound** checkbox sits in the top-right corner (next to undo/redo, or alone on the Create screen; on short screens such as a landscape iPhone it moves into the **⋯** menu as Sound Effects); it is on by default and saved per device. The mapping lives in `runtime/include/kartpad/mii/editor_sounds.h`:

- Opening the editor or birthday sheet: `CTRL_WIN_POPUP`. Leaving without changes, Keep Editing, Cancel: `CTRL_WIN_POPDOWN`. A confirmation appearing: `YESNO_POPUP`.
- Category tabs, page modes, colour swatches, face front, Mac birthday menus: `TAB_OK`. Part tiles and the ⋯ menu: `BTN_OK`. Gender, toggling on, Done, Animate Preview: `RADIO_OK`. Opening the look-alike grid: `BTN_OK`; Shuffle: `PAGE_NEXT`; Back: `PAGE_PREV`. Choosing what is already chosen, toggling off, nothing to undo or redo: `TAB_OK_NONE`. Start from scratch or picking a look-alike: `MATCH_CAPSULE_MII`.
- Adjustments and turning: `UD_LEFT` / `UD_RIGHT` on the first press; held repeats tick with `BTN_IN`, and a hold that reaches the limit plays `CTRL_REJECT`. Height and weight tick every 8 of 128 steps while dragging and on every key or VoiceOver step.
- Pages, undo and redo: `PAGE_PREV` / `PAGE_NEXT`; discarding or resetting changes also plays `PAGE_PREV`. Typing a name: `TENKEY_OK`; deleting: `TENKEY_ERASE`.
- Save or export: `DATA_SEND_OK`. Invalid names, save/export errors, pending-restart and unreadable Miis: `CTRL_REJECT`. Pointer hover (Mac, iPad trackpad): `BTN_IN`, which never cuts off another sound; every other sound replaces the one playing. Start Over: `PAGE_PREV`.

**Haptics (iPhone, iPad).** The sounds come with light haptics whether or not Sound is on: a selection tick for choosing, stepping, paging and slider notches, success for a save and a warning at a limit or error. Opening, closing, dialogs, typing, hover and choosing what is already chosen have none.

Sounds are rendered once per session on a background queue from the imported `files/sound/revo_kart.brsar` by `runtime/include/kartpad/audio/sound_archive.h`, an independent bounds-checked NW4R reader. It plays each sound's sequence through its instrument bank and DSP-ADPCM/PCM samples. Volume, pan, transpose, pitch bend, portamento, envelopes and note timing follow the sequence; sweeps apply instantly and LFO, filters and effect sends are not modelled, so the sounds are close to the game's, not identical. Nothing is cached on disk or shipped. Without the archive, or for a sound that fails to render, the editor stays silent. Playback uses the app's existing audio session, so the iPhone/iPad silent switch applies. The opening sound is requested before rendering finishes and plays if the sounds are ready within 1.5 s (about 0.9 s on a freshly booted iPhone simulator); otherwise it is skipped.

Mac defaults to 960 × 720 with an 800 × 600 minimum. Wide layouts show preview and editing panel side by side. The preview card carries the Mii's name and the turn left, face front and turn right controls. Pages show a pager only when a feature has more than one page; feature artwork is cropped and centred in its tile. Profile uses two columns when the panel is wide enough. Beside the panel, Save and Cancel sit under the preview with the status line above them, so the panel runs to the bottom edge; short screens (under 540 points tall, such as a landscape iPhone) drop the title and put the category tabs in the row with undo, redo and ⋯. Narrow portrait windows place the preview above the controls, split the category tabs across two rows and put the status line beside Save and Cancel. **Editing never scrolls.** Each page fits its panel: Profile tightens its spacing first, and a page that still doesn't fit splits into parts chosen from a strip of tabs on the panel's right edge, as Mii Maker does on small screens. Profile splits into Name (Nickname, Creator, Gender) and Details (Birthday, Favorite, Mingle, Favorite color); feature pages split into the style grid (one tab per switch position, such as Shape and Details or Mustache and Beard; otherwise Style), Color and Adjust (Flip hair or Mole, then the adjustments). The part resets to the first one when the category changes. At the 800 × 600 Mac minimum and on iPad every page fits whole; landscape iPhones split Profile and the busier feature pages. Regular adjustments update the affected controls and preview without rebuilding the form.

## Persistence

Save stages changes for the next cold launch. Export and discarded drafts leave live data untouched. Standard `.mii` records remain exactly 74 bytes. Hidden console identifiers, creation flags and reserved bits remain intact on edits. New identities use the runtime console MAC and a unique regular-Mii creation ID. Renaming an existing Mii updates matching licenses in Original and both Retro Rewind save locations.

A Mii whose fields are out of range (another tool can write one) opens unchanged. The preview, tiles and controls show the nearest valid value, and a field is stored in range only once it is edited; saving keeps the fields that weren't. A duplicate is a new Mii and takes the in-range values.

`PendingMiiChanges.plist` holds the queue: saved drafts, imports, removals, renames and license changes, in order. Each is checked against the queue replayed over the live files before it is added. The replayed files are kept in memory while the queue and the live files (by inode, size and change time) stay the same, so the Miis screen's refreshes don't replay the queue, and a new change is applied on top of them. On restart the queue is replayed over the latest database and saves, so race progress saved in the meantime is kept, and only then are the changed files backed up (database to `MiiBackups`, saves to `SaveBackups`). A Mii or license that no longer matches what a change expects rejects the whole queue, and nothing is written. Older versions' single-change files (`PendingRFL_DB.dat`, `PendingPlayerIdentity.plist`, `PendingLicenseChange.plist`) still apply first, and nothing is queued until they have.

`MiiEditorTransaction.plist` journals the replayed files before any live file changes. Atomic replacements write them. An interrupted commit rolls forward on the next launch, without replaying the queue again; gameplay is blocked until recovery succeeds. Backups retain the pre-application database and saves. There is no save-format migration.

## Imported resources and rendering

`files/contents/RFLRes01.arc` supplies original head meshes and feature textures. `files/Scene/Model/MiiBody.szs` supplies original small, medium and large male/female body meshes, standing animation, diffuse textures, light maps, highlight maps, material assignments and attachment data. These are the game package's racing outfits. No invented body geometry or replacement facial-feature artwork is used. Mii Channel clothing and interface assets are not present in this imported package; toolbar artwork is reconstructed as vectors from the Wii manual.

A shared Metal renderer in `MTKView` supports drag rotation, rotation buttons, front reset, viewport fitting and full-body/head framing. Resource readers validate bounds, primitives, matrix indices, finite geometry, texture dimensions and cache data. Positions, normals and UV coordinates use their separate original scales. Mirrored meshes preserve normals and winding. Face-mask composition uses original feature textures and recoloring. Transparent overlays do not write depth; filtering handles alpha without black fringes. Body vertex alpha is a light-map coefficient, while diffuse alpha masks highlights. Material IDs come from the original draw bytecode. Original attachment offsets align the collar and head.

Glasses textures use the original GX addressing modes, including mirrored U coordinates spanning both lenses. The GPU sampler and CPU thumbnail renderer preserve clamp/repeat/mirror metadata. Accessory thumbnails show both sides of the imported mesh; shared triangle edges are not blended twice.

Resources load on a serial background queue. Decoded resources are cached; stale revisions are discarded before installation. Archive SHA-256 and cache version invalidate replaced or incompatible data. A missing or damaged archive isn't read again until it (or Config.toml's game-data folder) changes, and a portrait that failed isn't retried until then. Portraits keep the 128 most recently used; feature tiles keep the most recently used within 24 MiB and are dropped when the editor closes. Cropped images hold only their own pixels. The preview's shader compiles off the main thread, starting when the Miis screen opens. Missing head/body resources or Metal availability produce a readable state, while editing and export remain available. Imported resources and decoded caches are not shipped in app packages.

## Validation and limits

Run `scripts/test-mii-builder.sh /absolute/path/to/RFLRes01.arc /absolute/path/to/MiiBody.szs /absolute/path/to/revo_kart.brsar`. Without resources, binary, history, sound-archive and Apple persistence tests still run. Sound-archive tests build synthetic archives (PCM8, PCM16 and DSP ADPCM waves, transposition, note timing, release tails, conditionals, 16-bit wrapping sequence variables, endless loops, non-advancing sequences, truncation and a corruption sweep); with the real archive every editor sound must render audibly. Tests use disposable databases and synthetic saves. Coverage includes all 46 field boundaries, fields out of range (drawn as their nearest valid value, kept by edits), Unicode, name trimming, checksums, reserved/identity preservation, capacity, unique IDs, linked-name/progress preservation, stale records, backups, interrupted recovery, creation, explicit feature mappings, selected pagination, grouped undo/redo, stale preview revisions, month lengths, decoded resources, addressing modes and malformed archives/caches.

Exact visual parity remains unverified. Feature IDs are mapped explicitly in Mii Channel order (hair, eyebrows, eyes, nose and mouth are non-sequential; the rest are sequential), taken from MiiJS's Mii Channel page tables and not yet checked against a console screen by screen. Body size follows the game: height + weight above 150 is a large Mii, above 104 medium, otherwise small (RMCP01 `0x80525FF4`). There is no continuous stretching; the preview swaps between the `sa_`, `ma_` and `la_mii` models and places the head with that build and gender's `miiDispParam.bin` head scale and Y/Z offset (menu copy in `MiiBody.szs`). The Body page names the current build. The lighting environment remains an approximation. Larger text scales within fixed controls; a full accessibility-size reflow is not implemented. Physical-device verification, every adjustment combination and an in-game rendering comparison are outstanding. These limits must not be presented as completed release gates.
